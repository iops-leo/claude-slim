# claude-slim

**あなたのClaude Codeは「こんにちは」と言う前にトークンを燃やしています。**

セッション開始のたびに、すべてのスキル、エージェント、スラッシュコマンド、メモリファイル、プラグイン指示がシステムプロンプトに読み込まれます — 一度も使わないものまで。しかもその代金は毎ターン発生します。claude-slimは、その起動時オーバーヘッドを計測し、不要なものを取り除きます。

プロキシも圧縮も使わず、Claude CodeとAPIの通信方法も一切変更しません — `~/.claude/`を読み取り、各スキルとプラグインの実際のコストを示し、不要な分だけを元に戻せる形で退避させます。

オーバーヘッドが潜む場所 — 実際の環境1台で計測した値：

| ソース | コスト | |
|--------|:---:|---|
| スキル一覧 | 〜10,100トークン | スキル256個 × それぞれの`名前: 説明`の1行 |
| エージェントカタログ | 〜2,250トークン | `~/.claude/agents/`、12個 |
| CLAUDE.md | 〜2,000トークン | プラグイン指示 |
| Deferred toolsリスト | 〜1,500トークン | MCPツールスキーマ |
| スラッシュコマンド | 〜80トークン | `~/.claude/commands/` |
| メモリファイル | **0 〜 63,500トークン** | 現在のプロジェクトのみ — プロジェクトごとの差が大きい |

最も過小評価されがちなのがスキル一覧です。インストール済みのスキルはそれぞれシステムプロンプトに`- 名前: 説明`の1行を加えますが、この1行は**30トークンのものから509トークンのものまで**あります。スキル60個といっても、請求額は同じではありません。

## コマンド1つ。5ステップ。

```
/claude-slim
```

```
 ┌────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌────────┐
 │  Scan  │ → │ Analyze │ → │ Propose │ → │ Execute │ → │ Report │
 │        │   │         │   │         │   │         │   │        │
 │すべて  │   │ 壊れた  │   │ユーザー │   │.disabled│   │before  │
 │  の    │   │ 重複    │   │  が     │   │  へ     │   │  vs    │
 │ 測定   │   │ 肥大化  │   │ 選択    │   │  移動   │   │ after  │
 └────────┘   └─────────┘   └─────────┘   └─────────┘   └────────┘
```

**Scan** — すべてを測定：ローカルスキル、プラグインスキル、CLAUDE.md、メモリファイル、MCPサーバー。

**Analyze** — 無駄を自動検出：

| | 検出対象 |
|---|---|
| 壊れたシンボリックリンク | スキルパック削除後の残骸 |
| 重複スキル | 複数ソースから同一スキル登録 |
| 空テンプレート | コンテンツのないプレースホルダー |
| 大容量ファイル | 10KB以上のSKILL.md |
| **未使用スキル** | **直近 N 日（既定 60 日）のセッションで一度も呼ばれていないローカルスキル** |
| エージェント・コマンド | `~/.claude/agents/` と `~/.claude/commands/` — 計測して報告するのみ、変更はしない |
| 古いメモリ | 毎セッション読み込まれる大容量メモリ |

**Propose** — 3段階に分類、あなたが決定：

| 段階 | アクション | 例 |
|------|-----------|---|
| **Auto** | 事前選択 | 壊れたリンク、空テンプレート |
| **Recommended** | 推奨 | 重複、古いメモリ |
| **Optional** | ユーザー判断 | まだ使うかもしれない大容量スキル |

**Execute** — 選択したスキルとプロジェクトメモリを `~/.claude/skills.disabled/` に移動します。失敗したインストールの一時キャッシュと壊れた symlink ファイルだけは恒久的にクリーンアップされ、選択前に permanent と表示されます。

**Report** — 何が変わったか正確に表示：

```
┌────────────────┬──────────┬──────────┬────────────┐
│                │  Before  │  After   │  節約      │
├────────────────┼──────────┼──────────┼────────────┤
│ ローカルスキル  │    65    │    15    │  -50       │
│ システムプロンプト│   ~80   │   ~48    │  -32       │
│ メモリファイル   │   15KB   │    2KB   │  -13KB     │
│ 推定トークン    │  ~8,500  │  ~4,200  │  ~4,300    │
└────────────────┴──────────┴──────────┴────────────┘
```

## 使い方

```bash
/claude-slim              # フルパイプライン
/claude-slim scan         # レポートのみ（変更なし）
/claude-slim doctor       # スキャナー前提条件とセッションログ信頼度を確認
/claude-slim restore      # すべて復元
```

## 安全第一

| | |
|---|---|
| **ユーザーデータは非破壊** | スキルとプロジェクトメモリは `~/.claude/skills.disabled/` に移動 |
| **復元可能** | 移動されたスキルとプロジェクトメモリは `/claude-slim restore` で復元 |
| **ユーザー制御** | 対話モードでは変更前に確認。`--dry-run` でプレビュー、`--auto` は Tier 1 のみ選択 |
| **危険領域に非接触** | CLAUDE.md、settings.json、プラグイン設定、`~/.claude/agents/`、`~/.claude/commands/` には触れない |
| **パス封じ込め** | 対象パスが `~/.claude/` の外に出る場合、破壊的操作をすべて拒否 |

## 動作原理

claude-slimは以下をスキャンします。プラグイン固有ロジックなし — 純粋なファイルシステム分析。

```
~/.claude/
├── skills/                  ← ユーザーインストールスキル
├── plugins/cache/           ← プラグインのスキル・エージェント・コマンド・MCPサーバー
├── agents/                  ← ユーザーエージェント（計測のみ、読み取り専用）
├── commands/                ← ユーザースラッシュコマンド（計測のみ、読み取り専用）
├── CLAUDE.md                ← プラグイン指示（読み取り専用）
├── projects/*/memory/       ← 自動メモリファイル（現在のプロジェクトのみ起動コストに算入）
└── settings.json            ← MCPサーバー数（読み取り専用）
```

どのプラグインの組み合わせでも動作：OMC、gstack、カスタムスキル、マーケットプレイスプラグイン、または何もなくても。

## 実績

数ヶ月間スキルが蓄積した環境での実際のクリーンアップ結果：

| 指標 | Before | After | |
|------|:------:|:-----:|---|
| ローカルスキル | 65 | 15 | **-77%** |
| システムプロンプトスキル | 〜80 | 〜48 | **-40%** |
| メモリファイル | 15KB | 2KB | **-87%** |
| **推定トークン節約** | | **〜4,300/セッション** | |

### 数値についての注記

claude-slim が報告するのは、**今いるディレクトリ**でセッションを開いた場合のコストです。メモリはプロジェクト単位で、Claude Code が読み込むのは現在のプロジェクトの `~/.claude/projects/<slug>/memory/` だけで、ディスク上の他のプロジェクトは読み込みません。別々のリポジトリで `scan` を実行すれば合計が変わるのは正常な挙動です。

トークン数は [js-tiktoken](https://github.com/nicolo-ribaudo/js-tiktoken) で実ファイルの内容を数えて求めています。推定値として残っているのは `~` が付いた2つだけです：MCPツールスキーマ（1ツールあたり〜8トークン）と、フロントマターを解析できなかったスキル（〜30トークン）。それ以外はすべて実測値です。

## v2.8.0 の変更点 (2026-07-25)

精度改善リリース。報告していた数値のうち3つが誤っており、最大のものは桁単位で誤っていました。**アップグレード後に起動トークン推定値が大きく減った場合、誤っていたのは以前の数値です。**

- **起動トークン推定から全プロジェクトのメモリ合算を撤廃。** Claude Codeは現在のプロジェクトの`memory/`のみを読み込むにもかかわらず、ディスク上のすべてのプロジェクトを合計していました。つまり「tokens at session start」という名前の値が、これまでに開いたプロジェクト数に比例して膨らんでいました。開発マシンでは**116,259トークンと報告されていた値の実際のセッションコストは14,399**でした。現在は当該プロジェクトのみに限定され、全体合計は「セッションあたりのコストではない」と明示して別途表示されます。
- **スキル一覧のコストを定数ではなく実測に変更。** 各スキルはシステムプロンプトに`- 名前: 説明`の1行を加えますが、従来はすべて固定値30トークンで計算していました。インストール済みスキル68個の実測分布は**30〜509トークン（平均51）** — 合計で70%の過小計上でした。v2.7.0のプラグイン別コスト勾配が「説明の長いスキル5個」と「短いスキル5個」を区別できなかった問題も解消されています。
- **`~/.claude/agents/`と`~/.claude/commands/`のスキャンを追加。** 毎セッションのシステムプロンプトに載るにもかかわらず、スキャナから完全に抜け落ちていました（開発マシンでエージェント12個、約2,254トークン）。**計測・報告のみ** — 移動も削除もしません。復元経路がない状態で破壊的動作を入れると、このツールの中核的な約束が壊れるためです。
- **プラグインマニフェストのバージョン固着を修正。** `.claude-plugin/*`が3リリースにわたり2.7.0のままでした。`claude plugin install`は`package.json`ではなくマニフェストを読むため、プラグイン利用者にはずっと旧バージョンが表示されていました。CIチェック（`npm run check:versions`）で再発を防ぎます。
- **トークンキャッシュの無制限な増大を修正。** 開発マシンでは776件中355件（46%、139KB）が既に削除済みのファイルを指していました。

テスト: 206 → **241 (+35)**。

## v2.7 の新機能

- **未使用プラグインの検出** — セッショントランスクリプトから MCP ツール呼び出し(`mcp__plugin_<プラグイン>_<サーバー>__*`)とスラッシュコマンドを併せて解析し、直近 60 日でスキル・MCP・コマンドのいずれも呼ばれていないプラグインを表示します。Tier 3（Optional、既定では未選択）なのでユーザーが判断します。クリーンアップ時は `claude plugin disable <name>` が自動実行され、`/claude-slim restore` で戻せます。
- **PLUGIN BREAKDOWN テーブル** — スキャンレポートにプラグイン別トークン内訳（CLAUDE.md セクション + スキル登録 + MCP deferred ツール + コマンド）と使用状況（used / unused / agent-only / insufficient data / disabled）が追加されました。実測上位例: `oh-my-claudecode` ~6,210 tok、`pm-skills` 系合計 ~2,500 tok。
- **セッションパーサーのバグ修正** — 文字列形式の user メッセージ（直接のスラッシュコマンド）が取りこぼされていた問題を修正。string / array の両方が正しく集計されます。
- **+82 テスト** 追加（新規モジュールとパーサーの回帰）。

## v2.7.1 (2026-07-20)

- **`unused_plugin` の節約量が常に 0 だった問題を修正** — 検出器が算出済みのプラグイン費用を使わず、dry-run とレポートで節約量を過小計上していたバグ。`pluginCosts` マップを DetectorContext に配線し、実値を反映します。
- **`duplicate` 検出器の名前空間誤検知を修正** — `org/ship` のような名前空間付きローカルスキルがプラグイン側 `ship` と重複と誤判定される問題。完全一致のみを重複扱いにします。
- **`stale_project` の復元パス範囲を強化** — 改ざんされたマニフェストが project-memory バックアップをスキルディレクトリへ流し込める余地を型別サブツリーガードで封じました。
- **非対話シェルで `--auto`/`--dry-run` を伴わない clean を拒否** — 以前は Tier 1 を暗黙適用していましたが、警告を出して exit 1 とし、明示的な opt-in を必須にしました。
- **`--lookback-days 0` と `--sessions-per-day 0` を尊重** — `parseInt() || N` が明示的な 0 を既定値へ格上げしていたバグを修正。
- **`claude-slim report` が zero-token クリーンアップ (broken_symlink / temp_cache) のみの履歴も表示するように**。

## v2.6 の新機能

- **`claude-slim doctor`** — Node 対応状況、`~/.claude/` の読み取り、ローカルスキル/プラグインキャッシュ、`claude plugin list`、最近のセッションログ信頼度を確認します。スキャン結果が少ない場合や未使用スキル検出が抑制された場合の診断に使えます。
- **安全説明の明確化** — スキルとプロジェクトメモリは `~/.claude/skills.disabled/` へ移動され復元可能です。壊れた symlink ファイルと失敗した `temp_local_*` キャッシュだけが permanent なクリーンアップ対象として表示されます。
- **開発 Node バージョン固定** — `.nvmrc` と `.node-version` を Node 22.12.0 に固定し、Vitest/Vite/Rolldown の現在の patch-floor 要件に合わせました。

## v2.4 の新機能

- **未使用スキルの検出** — `~/.claude/projects/*/*.jsonl` のセッショントランスクリプトを読み、直近 60 日間に `Skill` ツールから一度も呼ばれていないローカルスキルを表示します。Tier 3（Optional、既定では未選択）なのでユーザーが自分で選びます。`--lookback-days <n>` でウィンドウを調整可能。セッション数が 3 件未満、または呼び出しイベントが 0 件（スキーマ変更の可能性）の場合は分類自体を抑制し、データの信頼性が低いときに誤検知を出しません。
- **プラグインスキルは意図的に対象外**。`~/.claude/plugins/cache/` 配下のスキルは Claude Code のプラグインランタイムが管理しており、ファイルを移すと部分的にアンインストールされた状態になります。プラグイン単位の整理は `claude plugin disable <name>` を使ってください。
- **セッション使用キャッシュ** — `~/.claude/.skill-usage-cache.json` に mtime キーで保存。再スキャンでは変更されたセッションログだけを再解析します。
- **Node 20+** が新しいエンジン最低バージョンになりました（以前は `>=18`。Node 18 は v2.3.0 で CI マトリクスから既に削除済み）。

## v2.3 の新機能

- **Detector レジストリへのリファクタ (v2.3.0)** — 588 行の単一モジュールだったスキャナを `src/scanner/` 配下の小さな Detector 群へ分割。新しいヒューリスティックの追加が関数 1 つの追記で済むようになりました（CONTRIBUTING.md 参照）。公開 API は変更なし。
- **パス封じ込めガード (v2.2.3)** — すべての破壊的操作が `~/.claude/` 外を指す対象パスを拒否。`runCommand` はシェルを経由せず実行。`temp_cache` のクリーンアップは symlink-safe。
- **レポート符号バグ修正 (v2.2.3)** — 2.2.x 初期に分解テーブルの Saved カラムの符号が反転していた問題を修正。各行で正しい節約量を表示。
- **テスト 85 件（以前は 73 件）** — パス封じ込め、restore ガード、分解テーブル符号、restore-selection の重複排除、トークンキャッシュの atomic flush、カスタム Detector 注入のテストを追加。

## v2.2 の新機能

- **`stale_project` のアトミックな clean/restore** — ファイル単位のループではなく、ディレクトリ全体を 1 回の `rename()` で移動。途中で中断しても、ファイルが元とバックアップに分散する「部分失敗」状態は発生しません。
- **衝突時の明確なエラー** — すでにバックアップが存在するプロジェクトの clean、または既存ディレクトリ上への restore は、OS の難解なエラーではなく、対処法を示すメッセージで失敗します。
- **マニフェスト v2 スキーマ** — 現在無効化されているエントリだけを含む単一 JSON ファイル（`manifest.json`）。restore でエントリ自体を削除するため、clean/restore サイクルを繰り返してもサイズが無限に増加しません。
- **v1 からの自動マイグレーション** — 既存のレガシーマニフェスト（`.claude-slim-manifest.jsonl`）は初回読み取り時に v2 へ自動変換。原本は `.jsonl.bak` として保存されます。
- **クラッシュ安全な書き込み** — tmp ファイルに書き込んでから atomic rename するパターン。停電や SIGKILL でもマニフェストが壊れません。
- **テストカバレッジの拡充** — 66 テスト（以前は 35）。イシュータイプごとの round-trip テスト：`broken_symlink`、`template`、`duplicate`、`skill_dup`、`oversized_skill`、`temp_cache`、`stale_project`。マイグレーションと bounded-growth サイクルテストも追加。
