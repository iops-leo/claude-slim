# claude-slim

**あなたのClaude Codeは「こんにちは」と言う前にトークンを燃やしています。**

セッション開始のたびに、すべてのスキル、エージェント、スラッシュコマンド、メモリファイル、プラグイン指示がシステムプロンプトに読み込まれます — 一度も使わないものまで。しかもその代金は毎ターン発生します。claude-slimは、その起動時オーバーヘッドを計測し、不要なものを取り除きます。

プロキシも圧縮も使わず、Claude CodeとAPIの通信方法も一切変更しません — `~/.claude/`を読み取り、各スキルとプラグインの実際のコストを示し、不要な分だけを元に戻せる形で退避させます。

オーバーヘッドが潜む場所 — 実際の環境1台で計測した値：

| ソース | コスト | |
|--------|:---:|---|
| スキル一覧 | 〜10,100トークン | スキル256個 × それぞれの`名前: 説明`の1行 |
| エージェントカタログ | 〜2,250トークン | `~/.claude/agents/`、12個 |
| CLAUDE.md | 〜2,000トークン | プラグイン指示 |
| Deferred toolsリスト | 〜1,500トークン | MCPツールスキーマ |
| スラッシュコマンド | 〜80トークン | `~/.claude/commands/` |
| メモリファイル | **0 〜 63,500トークン** | 現在のプロジェクトのみ — プロジェクトごとの差が大きい |

最も過小評価されがちなのがスキル一覧です。インストール済みのスキルはそれぞれシステムプロンプトに`- 名前: 説明`の1行を加えますが、この1行は**30トークンのものから509トークンのものまで**あります。スキル60個といっても、請求額は同じではありません。

## コマンド1つ。5ステップ。

```
/claude-slim
```

```mermaid
flowchart LR
    A["<b>Scan</b><br/>すべてを測定"] --> B["<b>Analyze</b><br/>壊れた · 重複 · 肥大化"]
    B --> C["<b>Propose</b><br/>ユーザーが選択"]
    C --> D["<b>Execute</b><br/>.disabled へ移動"]
    D --> E["<b>Report</b><br/>before vs after"]
```

**Scan** — すべてを測定：ローカルスキル、プラグインスキル、CLAUDE.md、メモリファイル、MCPサーバー。

**Analyze** — 無駄を自動検出：

| | 検出対象 |
|---|---|
| 壊れたシンボリックリンク | スキルパック削除後の残骸 |
| 重複スキル | 複数ソースから同一スキル登録 |
| 空テンプレート | コンテンツのないプレースホルダー |
| 大容量ファイル | 10KB以上のSKILL.md |
| **未使用スキル** | **直近 N 日（既定 60 日）のセッションで一度も呼ばれていないローカルスキル** |
| エージェント・コマンド | `~/.claude/agents/` と `~/.claude/commands/` — 計測して報告するのみ、変更はしない |
| 古いメモリ | 毎セッション読み込まれる大容量メモリ |

**Propose** — 3段階に分類、あなたが決定：

| 段階 | アクション | 例 |
|------|-----------|---|
| **Auto** | 事前選択 | 壊れたリンク、空テンプレート |
| **Recommended** | 推奨 | 重複、古いメモリ |
| **Optional** | ユーザー判断 | まだ使うかもしれない大容量スキル |

**Execute** — 選択したスキルとプロジェクトメモリを `~/.claude/skills.disabled/` に移動します。失敗したインストールの一時キャッシュと壊れた symlink ファイルだけは恒久的にクリーンアップされ、選択前に permanent と表示されます。

**Report** — 何が変わったか正確に表示：

| | Before | After | 節約 |
|---|:---:|:---:|:---:|
| ローカルスキル | 65 | 15 | -50 |
| システムプロンプト | ~80 | ~48 | -32 |
| メモリファイル | 15KB | 2KB | -13KB |
| 推定トークン | ~8,500 | ~4,200 | ~4,300 |

## インストール

```bash
claude plugin marketplace add iops-leo/claude-slim
claude plugin install claude-slim
```

## 使い方

```bash
/claude-slim              # フルパイプライン
/claude-slim scan         # レポートのみ（変更なし）
/claude-slim doctor       # スキャナー前提条件とセッションログ信頼度を確認
/claude-slim check-update # より新しいバージョンが出ているか確認
/claude-slim restore      # すべて復元
```

## 安全第一

| | |
|---|---|
| **ユーザーデータは非破壊** | スキルとプロジェクトメモリは `~/.claude/skills.disabled/` に移動 |
| **復元可能** | 移動されたスキルとプロジェクトメモリは `/claude-slim restore` で復元 |
| **ユーザー制御** | 対話モードでは変更前に確認。`--dry-run` でプレビュー、`--auto` は Tier 1 のみ選択 |
| **危険領域に非接触** | CLAUDE.md、settings.json、プラグイン設定、`~/.claude/agents/`、`~/.claude/commands/` には触れない |
| **パス封じ込め** | 対象パスが `~/.claude/` の外に出る場合、破壊的操作をすべて拒否 |
| **Codex は読み取り専用** | `~/.codex/` があれば計測・報告のみ、移動も削除もしない |

## 動作原理

claude-slimは以下をスキャンします。プラグイン固有ロジックなし — 純粋なファイルシステム分析。

```
~/.claude/
├── skills/                  ← ユーザーインストールスキル
├── plugins/cache/           ← プラグインのスキル・エージェント・コマンド・MCPサーバー
├── agents/                  ← ユーザーエージェント（計測のみ、読み取り専用）
├── commands/                ← ユーザースラッシュコマンド（計測のみ、読み取り専用）
├── CLAUDE.md                ← プラグイン指示（読み取り専用）
├── projects/*/memory/       ← 自動メモリファイル（現在のプロジェクトのみ起動コストに算入）
└── settings.json            ← MCPサーバー数（読み取り専用）
```

どのプラグインの組み合わせでも動作：OMC、gstack、カスタムスキル、マーケットプレイスプラグイン、または何もなくても。

## 実績

数ヶ月間スキルが蓄積した環境での実際のクリーンアップ結果：

| 指標 | Before | After | |
|------|:------:|:-----:|---|
| ローカルスキル | 65 | 15 | **-77%** |
| システムプロンプトスキル | 〜80 | 〜48 | **-40%** |
| メモリファイル | 15KB | 2KB | **-87%** |
| **推定トークン節約** | | **〜4,300/セッション** | |

### 数値についての注記

claude-slim が報告するのは、**今いるディレクトリ**でセッションを開いた場合のコストです。メモリはプロジェクト単位で、Claude Code が読み込むのは現在のプロジェクトの `~/.claude/projects/<slug>/memory/` だけで、ディスク上の他のプロジェクトは読み込みません。別々のリポジトリで `scan` を実行すれば合計が変わるのは正常な挙動です。

トークン数は [js-tiktoken](https://github.com/nicolo-ribaudo/js-tiktoken) で実ファイルの内容を数えて求めています。推定値として残っているのは `~` が付いた2つだけです：MCPツールスキーマ（1ツールあたり〜8トークン）と、フロントマターを解析できなかったスキル（〜30トークン）。それ以外はすべて実測値です。

## v2.10.0 の変更点 (2026-08-02)

Codex 対応。ただし Codex に実際に問えることまでに限定しています。

- **`~/.codex/` があれば自動で走査します。** ローカルスキル、プラグインスキル、エージェント、`AGENTS.md` の起動コストを別セクションとして報告します。`scan --json` に `codex` キーが増え、`--no-codex` で無効化できます。開発マシンでは**誰も計測していなかった 10,926 トークン**が判明し、その中には毎セッション 285 トークンを消費していたスキルのバックアップ（`.bak`）も含まれていました。
- Codex の `SKILL.md` フロントマターは Claude Code と同形式のため、既存のパーサーをそのまま使えます。エージェントだけが `<名前>.toml` の `description = "…"` 形式なので専用パーサーを追加し、導入済みの 18 個すべてで検証しました。
- **未使用スキル検出は Codex には提供せず、その事実をレポートに明記します。** Codex のセッションログに残るのは呼び出し履歴ではなく、システムプロンプトに注入されたスキル**一覧**です。ほぼすべてのスキルがほぼすべてのセッションに現れるため、これを使用シグナルとして扱えば全部が「使用中」と判定されます。セッションファイル 408 個、ログ DB 56,724 行、ツール登録テーブルまで確認した上での結論です。
- **`~/.codex/` は読み取り専用です。** `~/.claude/agents/` と同じく、移動も削除も行いません。

テスト: 279 → **302 (+23)**。

過去のリリースノートは [CHANGELOG.md](../CHANGELOG.md) を参照してください。
