# claude-slim

**あなたのClaude Codeは「こんにちは」と言う前にトークンを燃やしています。**

セッション開始のたびに、すべてのスキル、エージェント、スラッシュコマンド、メモリファイル、プラグイン指示がシステムプロンプトに読み込まれます — 一度も使わないものまで。しかもその代金は毎ターン発生します。claude-slimは、その起動時オーバーヘッドを計測し、不要なものを取り除きます。

プロキシも圧縮も使わず、Claude CodeとAPIの通信方法も一切変更しません — `~/.claude/`を読み取り、各スキルとプラグインの実際のコストを示し、不要な分だけを元に戻せる形で退避させます。

オーバーヘッドが潜む場所 — 実際のセッション1回の開始時に Claude Code が送った内容を、そのセッションログから読み戻した値：

| ソース | コスト | |
|--------|:---:|---|
| MCPツール名 | 〜10,700トークン | 768個。ツール検索が後回しにするのはスキーマで、名前ではない — コネクタ1つだけで160個 |
| スキル一覧 | 〜8,200トークン | スキル213個、コンテキストウィンドウの1%が上限 — **うち99個は名前だけ表示** |
| 指示ファイル | 〜6,300トークン | CLAUDE.md、`@path` インポート、`paths:` のないルール、プロジェクトの `MEMORY.md` |
| MCPサーバー指示 | 〜3,600トークン | サーバー10個、claude.ai コネクタを含む |
| エージェントカタログ | 〜2,200トークン | エージェント33個 |

スキル一覧には予算があります。コンテキストウィンドウの1%で、200kモデルなら6,000文字、1Mなら30,000文字です。これを超えても Claude Code はプロンプトを増やしません。使用頻度の低いスキルから順に、説明を黙って削ります。そのスキルはインストールされたままで呼び出しもできますが、モデルには `- skill-name` しか見えないため、いつ使えばいいのか判断できません。上の環境では、スキルの半分近くがこの状態でした。

## コマンド1つ。5ステップ。

```
/claude-slim
```

```mermaid
flowchart LR
    A["<b>Scan</b><br/>すべてを測定"] --> B["<b>Analyze</b><br/>壊れた · 重複 · 肥大化"]
    B --> C["<b>Propose</b><br/>ユーザーが選択"]
    C --> D["<b>Execute</b><br/>.disabled へ移動"]
    D --> E["<b>Report</b><br/>before vs after"]
```

**Scan** — すべてを測定：ローカルスキル、プラグインスキル、CLAUDE.md、メモリファイル、MCPサーバー。

**Analyze** — 無駄を自動検出：

| | 検出対象 |
|---|---|
| 壊れたシンボリックリンク | スキルパック削除後の残骸 |
| 重複スキル | 複数ソースから同一スキル登録 |
| 空テンプレート | コンテンツのないプレースホルダー |
| 大容量ファイル | 10KB以上のSKILL.md |
| **未使用スキル** | **直近 N 日（既定 60 日）のセッションで一度も呼ばれていないローカルスキル** |
| エージェント・コマンド | `~/.claude/agents/` と `~/.claude/commands/` — 計測して報告するのみ、変更はしない |
| **未使用プラグイン** | **直近 N 日（既定 60 日）のセッションでスキル・MCP・コマンドが一度も呼ばれていないプラグイン。Tier 3、自動選択はしない。** |
| **未使用 MCP サーバー** | **`~/.claude.json` の user・local スコープのサーバーのうち、直近 N 日でツールが一度も呼ばれていないもの。Tier 3、自動選択はしない。`claude mcp remove` で削除し、定義は `restore` 用に保管。** |
| 肥大化したメモリインデックス | 5KB 超、または 200 行 / 25KB の起動上限で切られて末尾が読み込まれない `MEMORY.md` |
| ルール & インポート | `~/.claude/rules/` と CLAUDE.md の `@path` インポート — 測定・報告のみ、変更しない |
| 無効化プラグイン | インストール済みだが無効のままキャッシュを占有 |
| 古いプロジェクト | 90日以上触れられていないプロジェクトメモリ |
| 一時キャッシュ | プラグインインストール失敗の残骸（`temp_local_*`） |

**Propose** — 3段階に分類、あなたが決定：

| 段階 | アクション | 例 |
|------|-----------|---|
| **Auto** | 事前選択 | 壊れたリンク、空テンプレート、一時キャッシュ |
| **Recommended** | 推奨 | 重複、古いメモリ、無効化プラグイン、古いプロジェクト |
| **Optional** | ユーザー判断 | まだ使うかもしれない大容量スキル |

**Execute** — 選択したスキルとプロジェクトメモリを `~/.claude/skills.disabled/` に移動します。失敗したインストールの一時キャッシュと壊れた symlink ファイルだけは恒久的にクリーンアップされ、選択前に permanent と表示されます。

**Report** — 何が変わったか正確に表示：

| | Before | After | 節約 |
|---|:---:|:---:|:---:|
| ローカルスキル | 65 | 15 | -50 |
| システムプロンプト | ~80 | ~48 | -32 |
| メモリファイル | 15KB | 2KB | -13KB |
| 推定トークン | ~8,500 | ~4,200 | ~4,300 |

## インストール

```bash
claude plugin marketplace add iops-leo/claude-slim
claude plugin install claude-slim
```

[skills.sh](https://skills.sh) ディレクトリからも導入できます。この経路は Codex・Cursor・OpenCode にも
スキルを配置します。ただし claude-slim が*解析する*対象は `~/.claude/` と `~/.codex/` のままです。

```bash
npx skills add iops-leo/claude-slim
```

## 使い方

```bash
/claude-slim              # フルパイプライン
/claude-slim scan                     # レポートのみ（変更なし）
/claude-slim scan --project-dir PATH  # PATH のプロジェクトメモリを集計（既定: cwd）
/claude-slim doctor                   # スキャナー前提条件とセッションログ信頼度を確認
/claude-slim check-update             # より新しいバージョンが出ているか確認
/claude-slim restore                  # すべて復元
```

## 安全第一

| | |
|---|---|
| **ユーザーデータは非破壊** | スキルとプロジェクトメモリは `~/.claude/skills.disabled/` に移動 |
| **復元可能** | 移動されたスキルとプロジェクトメモリ、削除した MCP サーバーは `/claude-slim restore` で復元 |
| **ユーザー制御** | 対話モードでは変更前に確認。`--dry-run` でプレビュー、`--auto` は Tier 1 のみ選択 |
| **危険領域に非接触** | CLAUDE.md、settings.json、プラグイン設定、`~/.claude/agents/`、`~/.claude/commands/` には触れない |
| **パス封じ込め** | 対象パスが `~/.claude/` の外に出る場合、破壊的操作をすべて拒否 |
| **MCP は Claude Code 経由のみ** | `~/.claude.json` を直接編集しない。選択した MCP サーバーは `claude mcp remove` で削除し、定義は `~/.claude/skills.disabled/.mcp-backup/` に権限 0600 でバックアップ |
| **Codex も同じ規則** | `~/.codex/` も同じ 3 段階で整理。移動先は `~/.codex/skills.disabled/` で `restore` により復元 |
| **エージェント間分離** | パスガードがエージェント単位のため、Codex の項目が `~/.claude/` に、またその逆にも届かない |

## 動作原理

claude-slimは以下をスキャンします。プラグイン固有ロジックなし — 純粋なファイルシステム分析。

```
~/.claude/
├── skills/                  ← ユーザーインストールスキル
├── plugins/cache/           ← プラグインのスキル・エージェント・コマンド・MCPサーバー
├── agents/                  ← ユーザーエージェント（計測のみ、読み取り専用）
├── commands/                ← ユーザースラッシュコマンド（計測のみ、読み取り専用）
├── CLAUDE.md                ← システム指示 + @インポート（読み取り専用）
├── rules/                   ← ユーザールール（測定、読み取り専用。パス限定は別表示）
├── projects/*/memory/       ← 自動メモリ（現在のプロジェクトの MEMORY.md のみ起動コストに算入）
├── projects/*/*.jsonl       ← セッションログ：何を呼び出したか、最新のセッションが何を読み込んだか（読み取り専用）
└── settings.json            ← 設定（読み取り専用。ここに定義された MCP サーバーは「読み込まれない」と表示）
~/.claude.json               ← user・local スコープの MCP サーバー
<project>/.mcp.json          ← project スコープの MCP サーバー（読み取り専用）
```

どのプラグインの組み合わせでも動作：OMC、gstack、カスタムスキル、マーケットプレイスプラグイン、または何もなくても。

## 実績

数ヶ月間スキルが蓄積した環境での実際のクリーンアップ結果：

| 指標 | Before | After | |
|------|:------:|:-----:|---|
| ローカルスキル | 65 | 15 | **-77%** |
| システムプロンプトスキル | 〜80 | 〜48 | **-40%** |
| メモリファイル | 15KB | 2KB | **-87%** |
| **推定トークン節約** | | **〜4,300/セッション** | |

### 数値についての注記

claude-slim が報告するのは、**今いるディレクトリ**でセッションを開いた場合のコストです。メモリはプロジェクト単位で、Claude Code が読み込むのは現在のプロジェクトの `~/.claude/projects/<slug>/memory/` だけで、ディスク上の他のプロジェクトは読み込みません。別々のリポジトリで `scan` を実行すれば合計が変わるのは正常な挙動です。そのプロジェクト内でも起動時に読み込まれるのは `MEMORY.md` の先頭 200 行または 25KB だけで、トピックファイルは Claude が読むまでコストがかかりません。

トークン数は [js-tiktoken](https://github.com/nicolo-ribaudo/js-tiktoken) で実ファイルの内容を数えて求めています。推定値として残っているのは `~` が付いた2つだけです：MCPツールスキーマ（1ツールあたり〜8トークン）と、フロントマターを解析できなかったスキル（〜30トークン）。それ以外はすべて実測値です。

**MEASURED AT SESSION START** はさらに一歩踏み込みます。最新のセッションログに Claude Code が記録した起動時のコンテキストを読むので、ディスクの解析では見えないもの — claude.ai コネクタ、MCPツール名、名前だけに削られたスキル — まで拾えます。スキル一覧が予算を超えている場合、推定値は予算分だけを数え、`RECOVERABLE` もそれを明示します。予算超過の一覧からスキルを削除しても、プロンプトは縮まず、削られていた説明が戻ってくるだけだからです。

## v2.17.0 の変更点 (2026-11-22)

- **追加: MEASURED AT SESSION START。** `scan` が、最新のセッションログに Claude Code が記録した起動時のコンテキスト（スキル一覧、MCPツール名、サーバー指示、エージェントカタログ、指示ファイル）を読み、次の内容を報告します：
  - **名前だけ表示されているスキル。** 一覧はコンテキストウィンドウの1%が上限で、超えると使用頻度の低いスキルから説明が外されます。該当するスキルをプラグインごとにまとめて表示し、未使用のものを整理すれば説明がいくつ戻るかも示します。
  - **二重に追加されたコネクタ** — 同じツール名を公開している2つの MCP サーバー（例：claude.ai コネクタと手動インストール）と、2つのサーバーがどちらも公開しているツール名。
  - Claude Code 自身のプロンプトを含めた、最初のターンの実際の入力サイズ。
- **変更: 推定値が一覧の予算に従うようになりました。** 予算を超えたスキル一覧は予算分で数え、`RECOVERABLE` も、スキルを削除しても解放できないトークンを約束しなくなりました。
- **修正: 未使用の判定。** `/name` と入力して使ったスキルや、`/plugin:command` 経由でしか使っていないプラグインが未使用と報告されていました。Claude Code 自身の `skillUsage` 記録も使用として数えるようになりました。「60日間呼び出しなし」はログが実際に持っている以上のことを主張していました — Claude Code はデフォルトで30日を過ぎたログを削除します。そこで検出結果ごとに何日分のログに基づくかを示し、`doctor` がログを長く残す方法を案内するようにしました。
- **修正: 復元と安全性。** Codex スキルを復元すると、同名の Claude スキルの記録が消えることがありました。壊れた `manifest.json` が警告なしに上書きされていました。`skills/` 配下にシンボリックリンクのフォルダがあると、clean が `~/.claude/` の外のファイルを移動できてしまいました。3つとも塞ぎました。
- その他の修正：アクティブなプロジェクトが古いプロジェクトとして提案される、プラグインの状態をプラグイン単位ではなくマーケットプレイス単位で判定する、TTY がないと `clean --dry-run` が実行を拒否する、`--project-dir` 指定時にクリーン後の数値が膨らむ、`CODEX_HOME` が無視される。

テスト: 580 → **703**。
